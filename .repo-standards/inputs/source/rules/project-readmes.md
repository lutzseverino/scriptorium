# Project README rules

Each maintained app, service, library, or tool with its own responsibility and
development commands is a Project and has a Project README, including internal
packages. Fixtures, generated code, and directories that only organize other
content are not Projects.

A Project README has a plain Markdown title and a concise developer-facing
description. It explains the Project's purpose, development commands, important
configuration, and relevant documentation, and states the working directory for
commands when it is not apparent. It links the shared setup and contribution
instructions in the root `docs/development/README.md` and `CONTRIBUTING.md`
instead of duplicating them, and each of those links renders text or visible
linked media. Its local links resolve.
